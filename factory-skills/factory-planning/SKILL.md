---
name: factory-planning
description: "Plan a software-factory change from a GitHub Issue before implementation. Use for new feature, bug, or maintenance work in a factory-enabled channel."
---

1. Find or create the GitHub Issue in the configured repository before starting substantial work. Do not treat a Slack message alone as the durable task record.
2. State the problem, acceptance criteria, affected repository, risks, and any explicit non-goals in the issue or linked plan.
3. Inspect the relevant code and tests before committing to an approach. Break larger work into independently reviewable issues when practical.
4. Keep the issue, Slack thread, branch, and PR cross-linked with public-safe URLs.
5. If GitHub access is unavailable, say so and record the limitation; do not invent an issue number.
